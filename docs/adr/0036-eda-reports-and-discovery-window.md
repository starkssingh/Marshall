# ADR 0036 — EDA reports and the discovery window

- **Status:** accepted
- **Date:** 2026-09-27
- **Tasks:** EDA-001 (used by EDA-002 … EDA-006)

## Context

EDA-001: a report framework — Python modules produce Markdown and PNG through a `ReportBuilder`;
optional Jupytext notebooks may only import library code; reports are saved with their
configuration and git sha; the discovery window is enforced. Acceptance: a deterministic build on
a fixture, and refusal of post-discovery data. Plan section 2: EDA runs only on a discovery window,
the first 50–60 % of the non-vault data, so hypotheses generated by looking at data are tested on
later folds. Sprint 5 is build-only (ADR 0035): the framework is tested on synthetic data only.

## Decision

1. **Layout.** `xq.research.reports` (plan section 3) holds the report builder and the discovery
   window; the EDA itself is the `xq.research.eda` package — its inputs (`data`), one module per
   EDA task, and `run`, which assembles the report. The CLI is `xq research eda --dataset <id>
   --hypothesis <H>`, replacing the placeholder `research` group.
2. **Configuration.** Every EDA parameter is in `config/eda.yaml` (a new section file, loaded as
   `AppConfig.eda`), fixed before any EDA result exists; changing one afterwards needs an ADR.
3. **The discovery window** is resolved per dataset: from the dataset's start, the first
   `discovery.fraction` (0.5, the low end of the plan's 50–60 %) of the span to `vault.start`,
   floored to a trading-day start (17:00 New York); or everything before `discovery.end` once the
   owner fixes it from the real data's depth. It is provisional until then. A bar belongs to the
   window if it starts at or after its start and **becomes available** at or before its end, so a
   bar straddling the end is outside.
4. **Enforcement, in three places.** `load_eda_inputs` asks the catalog (which enforces the vault)
   only for bars inside the window and drops those available after it; `EdaInputs` checks every
   frame against the window when it is built and raises `DiscoveryWindowError`; an explicit
   `--end` after the window's end is refused, never cut silently. Trading days the dataset's
   quality gate excluded are left out.
5. **Returns** are close-to-close log returns of bars **adjacent in market time** (no market-open
   time between the first bar's end and the second's start, `MarketClock`): returns across the
   daily break, weekends and closed holidays are kept, returns across missing or excluded bars are
   dropped. Each return carries its holding interval `[ret_start, ret_end)`.
6. **Reports.** `ReportBuilder` writes `index.md` (title, provenance, links), one Markdown file per
   section, tables as full-precision CSV (rendered in Markdown with a row limit where long),
   figures as PNG rendered by matplotlib's Agg canvas outside pyplot's global state and without
   software or time metadata, `metadata.json` (dataset, window, git sha, `uv.lock` hash, seed,
   configuration and its hashes, cost basis) and `manifest.json` (SHA-256 of every file). The run
   id and the confirmatory flag go to `run.json`, outside the manifest. The same dataset,
   configuration, commit, lockfile and seed give byte-identical files (tested end to end). Every
   file is recorded as a run artifact. Reports are under `reports/eda/<dataset_id>/<run_id>/`
   (git-ignored, like the board).
7. **Runs and trials.** EDA runs go through `experiment_run` (kind `eda`) and need a registered
   hypothesis. They evaluate no trading configuration, so they record **no trials**; the
   multiplicity of the descriptive effects is corrected inside the report (EDA-004's family-wise
   intervals), and hypotheses it suggests are pre-registered and tested on later data.
8. **Notebooks.** None exist. If one is added, it is a Jupytext `.py` notebook that only imports
   and calls library code; it never computes a reported number itself.

## Consequences

- `xq research eda --dataset <id>` regenerates every table and figure in one command (the plan's
  acceptance), tested on a synthetic dataset only.
- The first real-data EDA needs a registered hypothesis for its run (an EDA pre-registration is an
  open owner item) and the discovery window fixed from the data's depth.
- A dataset that starts after the discovery window ends cannot be described.
